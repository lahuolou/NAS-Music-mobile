## 2. 变更总览

- **一句话目标**：全仓消除 unchecked cast（`as NasMusicApp` 类断言）与 `!!` 非空断言，统一改为安全写法，把 null 路径从「崩溃」降级为「跳过/早退/兜底」，行为兼容。
- **改动类型**：重构（类型安全）/ 防御性修复；无 bugfix、无性能专项、无依赖变更、无交互/渲染效果变更。
- **范围**：约 42 个源文件（visualizer 9 + player 1 + UI/ViewModel 19 + backend 8 + 组件 5，去重后），全部为 `.kt` 源码，无资源/配置/依赖/构建脚本改动。
- **风险等级**：低（改动全部为语义等价的 null 安全化；唯一行为差异见第 4 节「异常路径」）。
- **行为兼容**：是（正常路径行为完全一致；异常路径由「抛 NPE」改为「跳过该绘制/该条目/返回 null」）。

| :680 | `codec.getInputBuffer(inputIndex)!!` → `?: continue` |

**为什么**：① `getInputBuffer`/`getOutputBuffer` 是 MediaCodec 官方文档标注**可能返回 null** 的 API（队列满/超时），`!!` 是真实崩溃点；② `format.getString(KEY_MIME)` 可返回 null；③ 其余为「刚赋值/已保证非空」的冗余断言。输出契约（`decodeAudioToTempFile` 恒输出 44100Hz 立体声，`writeWavHeader`/`patchWavDataSize` 用 `SAMPLE_RATE`/`CHANNEL_COUNT` 常量）**未触碰**。
**影响范围**：仅 `DemucsSeparator.kt` 内部；对外 `initialize/separate/release` 签名不变。
**兼容性**：兼容。异常路径：原「getInputBuffer null → NPE 崩溃」→「跳过该次填充/输出重试」；MIME null 原「NPE → catch 记录 decode_failed」→「显式同路径返回 null」。
**验证**：compileDebugKotlin 一轮过；全量测试含人声分离相关用例（无失败）。
**风险**：低。`continue` 依赖 dequeue 的 10ms 超时避免忙循环；`outputBuffer` null 分支先 `releaseOutputBuffer` 防泄漏。
**回滚**：本文件无独立备份，按本表 + 会话编辑轨迹还原（详见第 8 节）。
